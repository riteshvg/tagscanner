2. Component Structure

2a. Content Script
        Injects into web pages to detect Adobe Tags implementations
        Extracts Launch data from the page's _satellite object
        Communicates findings back to the extension
2b. Popup Interface (popup.js/html)
        Entry point for user interaction
        Displays initial property information
        Provides navigation to detailed analysis views
        Stores extracted data in sessionStorage
2c. Summary View (summary.js/html)
        Detailed analysis of Adobe Tags implementation
        Displays unused components and optimization opportunities
        Provides visualization and export functionality
        Reads data from sessionStorage
2d. Satellite Sandbox (satellite_sandbox.html)
        Isolated environment for script analysis
        Processes unminified Launch scripts
        Extracts container configuration

5. Key functionality

5a. Property Scanning
    Detect Adobe Tags implementation
    Extract property details and components
    Parse unminified script for deeper analysis
5b. Usage Analysis
    Identify unused data elements, rules, and extensions
    Calculate size/performance impact
    Detect dependencies between components
5c. Data Visualization
    Present component counts and usage statistics
    Display tables of unused components
    Allow sorting and filtering of components
5d. Export & Sharing
    Generate PDF reports for stakeholders
    Copy component tables as images
    Export full data as CSV
5e. User Experience
    Guided tour for first-time users
    Copy functionality for sharing specific sections
    Responsive design for different screen sizes

7. Data Storage

7a. SessionStorage Keys
    launch_property_name: Name of the Adobe Tags property
    launch_property_environment: Environment (Production/Development)
    tagScanner_version: Version of the TagScanner tool
    _satellite._container.dataElements: Cached data elements
    _satellite._container.rules: Cached rules data
    _satellite._container.extension: Cached extensions data
7b. LocalStorage Keys
    tagScannerTourShown: Track if guided tour was shown



    Optimized WebSDK Component Display
The new implementation provides:
Hierarchical Table View:
XDM data is displayed in a clean, organized table with clear columns
Each property in the XDM object is shown with its full path
You can see nested objects properly structured with parent-child relationships
Four Information Columns:
XDM Path: Shows the complete dot-notation path to each property
Value Type: Displays whether the value is a string, number, object, array, etc.
Preview: Shows a short preview of the value (truncated for longer values)
Actions: Interactive buttons for each field
Interactive Features:
Copy Path Button: For leaf nodes, you can copy the full XDM path with one click
View Full Path Button: For complex objects/arrays, opens a modal to see the complete subtree
Path copying provides visual feedback when copied to clipboard
Modal Dialogs:
When you click "View Full Path", a modal dialog appears
The dialog shows the complete JSON structure with syntax highlighting
Includes a close button and clear title showing which path you're viewing
Contents are scrollable for large objects
Better Error Handling:
Graceful error handling with clear error messages
Console logging for debugging issues
